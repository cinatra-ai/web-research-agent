## Directory Purposes

**`cinatra/`:**
- Purpose: Cinatra platform-facing artifacts required for marketplace registration and runtime
- Contains: `oas.json` — the complete Flow spec including StartNode, ApiNode, EndNode, DataFlowEdges, ControlFlowEdges, and referenced_components
- Key files: `cinatra/oas.json`

**`skills/web-research-agent/`:**
- Purpose: LLM system-prompt specification; auto-discovered by the Cinatra `/api/llm-bridge` via `agent_id: "web-research-agent"`
- Contains: `SKILL.md` — the step-by-step behavioral contract (input validation, per-row web_search loop, failure taxonomy, output envelope)
- Key files: `skills/web-research-agent/SKILL.md`

**`.github/workflows/`:**
- Purpose: CI/CD pipeline definitions
- Contains: `ci.yml` (runs the extension-kind-gate), `release.yml` (publish pipeline)
- Key files: `.github/workflows/ci.yml`, `.github/workflows/release.yml`

## Key File Locations

**Entry Points:**
- `cinatra/oas.json`: Flow definition and runtime entry point; `start_node` references the StartNode component

**Configuration:**
- `package.json`: Package identity, `cinatra.kind: "agent"`, `cinatra.apiVersion`, `cinatra.dependencies: []`
- `tsconfig.json`: TypeScript/module configuration (ES module, used for linting/IDE support of `extension-kind-gate.mjs`)
- `.npmrc`: npm registry configuration (existence only)

**Core Logic:**
- `skills/web-research-agent/SKILL.md`: All enrichment logic (LLM-interpreted); this is the behavioral source of truth
- `cinatra/oas.json`: All flow wiring — the ApiNode's `data.system` and `data.user` fields contain the LLM prompt template

**CI Tooling:**
- `extension-kind-gate.mjs`: Self-contained validation script; exports `validateAgent`, `validateWorkflow`, `validateBpmnSanity`, `validateWorkflowPackageShape`, `runGate`, `findWorkflowSidecars`, `parseArgs`

## Naming Conventions

**Files:**
- `SKILL.md`: UPPERCASE — Cinatra convention for LLM-facing skill specifications
- `oas.json`: lowercase — Cinatra convention for OpenAgentSpec flow manifest
- `extension-kind-gate.mjs`: kebab-case `.mjs` — Node ES module script

**Directories:**
- `cinatra/`: lowercase — Cinatra platform artifact directory (conventional name)
- `skills/<agent-name>/`: kebab-case matching the package slug and `agent_id`

## Where to Add New Code

**New behavioral logic (LLM instructions):**
- Edit `skills/web-research-agent/SKILL.md` — all enrichment steps, failure tags, output contracts, and tool-use discipline live here

**New flow inputs or outputs:**
- Edit `cinatra/oas.json` — update `inputs`/`outputs` arrays at the Flow level AND inside `$referenced_components.start` (StartNode) and `$referenced_components.end` (EndNode); add DataFlowEdge entries to route new fields through the ApiNode

**New CI validation rules:**
- Edit `extension-kind-gate.mjs` — add entries to `BANNED_PRIMITIVES` or `BANNED_TYPEHINTS`, or extend `validateAgent`/`validateWorkflow` functions

**New GitHub Actions:**
- Add workflow files under `.github/workflows/`

## Special Directories

**`cinatra/`:**
- Purpose: Required by Cinatra platform for agent registration; `oas.json` is the canonical flow spec
- Generated: No — hand-authored (or generated by Cinatra tooling and committed)
- Committed: Yes

**`skills/`:**
- Purpose: LLM skill specifications; auto-discovered by `/api/llm-bridge` via `agent_id` lookup
- Generated: No — authored as markdown
- Committed: Yes

**`.planning/`:**
- Purpose: GSD planning artifacts (codebase maps, phase plans)
- Generated: Yes (by GSD tooling)
- Committed: Optional (project-dependent)
